# DESIGN.md — «ГРАНЬ»

Дизайн-система лендинга. Описывает то, что **уже построено и согласовано
заказчиком**, а не желаемое. При добавлении новых блоков — держаться этих
токенов и правил.

Товар: журнальный столик из массива дуба со столешницей из закалённого стекла.

---

## Цвет

Источник истины — `@theme` в `src/app/globals.css`. Здесь только смысл токенов.

```yaml
colors:
  ink:          "#14120f"   # основной текст, кнопка, активные рамки
  ink-soft:     "#6b6560"   # вторичный текст, подзаголовок h1
  ink-faint:    "#9c948d"   # микро-подписи, плейсхолдеры, label-caps
  hair:         "#e8e5e1"   # волосяная рамка по умолчанию
  hair-strong:  "#d6d2cc"   # рамка поля ввода, hover
  paper:        "#ffffff"   # фон страницы
  paper-dim:    "#fbfaf9"   # подложка активного состояния
  oak:          "#c08b4c"   # ЕДИНСТВЕННЫЙ акцент — светлый дуб
  oak-soft:     "#e3c9a5"
  walnut:       "#6b4a2f"   # отделка «тёмный орех»
  wenge:        "#3a2c22"   # отделка «ценные породы»
  glass:        "#b9d3ca"   # кромка закалённого стекла
  error:        "#b3261e"
```

**Правила цвета**

- Фон страницы всегда `paper`. Секции не красятся — разделяются воздухом
  и волосяной линией, а не заливкой.
- `oak` / `walnut` / `wenge` — это **отделки изделия**, а не палитра интерфейса.
  Допустимы в точках выбора отделки и в буллете-точке. Кнопку ими не красить.
- Основная кнопка — сплошной `ink` с белым текстом. Второй по силе кнопки
  в системе нет: остальное — текстовые ссылки с подчёркиванием.
- Тёмной темы нет и не планируется (`colorScheme: "light"` в `layout.tsx`).

**Известное ограничение по контрасту.** `ink-faint` на белом даёт ≈3.0:1 — ниже
порога WCAG AA 4.5:1 для обычного текста. Сейчас применяется только к
декоративным микро-подписям (11–12px). Для любого текста, который нужно
прочитать, брать `ink-soft` (≈5.7:1). Новые смысловые подписи в `ink-faint`
не заводить.

## Типографика

```yaml
fonts:
  display: Inter Tight   # 500 600 700 800 900, latin + cyrillic
  body:    Inter         # 400
```

| Роль | Размер | Начертание | Трекинг |
| --- | --- | --- | --- |
| `h1` | `clamp(2.6rem, 6.4vw, 5.6rem)`, `leading-[0.92]` | 900 первая строка, 600 вторая в `ink-soft` | `-0.045em` |
| `h2` | 22px, `leading-none` | 800 | `-0.045em` |
| `h3` | 24px | 700 | `-0.045em` |
| Основной текст | 15px, `leading-relaxed` | 400, `ink-soft` | — |
| Мелкий текст | 13.5 / 12.5 px | 400, `ink-soft` | — |
| `label-caps` | 11px, uppercase | 600, `ink-faint` | `+0.16em` |

**Правила типографики**

- Заголовки — только `font-display` с `tracking-tightest`. Крупный кегль и
  отрицательный трекинг — главный носитель характера, экономить на нём нельзя.
- Приём заголовка: первая строка чёрная и жирная, вторая — светлее весом
  и цветом. Так задана иерархия в hero, повторять её в новых секциях.
- `label-caps` всегда идёт в паре с `ink-faint` и часто с ведущей чертой
  `<span className="h-px w-8 bg-hair-strong" />`.
- Единицы измерения и размеры — обычным текстом, без верхних индексов.
- Неразрывный пробел перед единицами: `10&nbsp;мм`.

## Форма и пространство

```yaml
radius:
  default: 0px          # ВЕЗДЕ
  exceptions:
    - точка-буллет 4×4 (rounded-full)
    - круг подтверждения 48×48 (rounded-full, только border)
shadow:
  none: true            # теней нет ни одной
spacing:
  container: max-w-[1440px]
  gutter:    px-5 / sm:px-8 / lg:px-12
  section:   pt-10 pb-14 / lg:pt-16 lg:pb-24
  grid-gap:  gap-12 / lg:gap-14
  card-pad:  p-6 / sm:p-8
```

**Правила формы**

- **Нулевой радиус — подпись системы.** Никаких `rounded-lg`, пилюль,
  капсульных кнопок и чипов. Если элемент просится скруглить — вместо этого
  дать ему волосяную рамку.
- **Теней нет.** Глубина строится рамкой `hair` и белым воздухом. `box-shadow`,
  `backdrop-blur`, стеклянные панели — не применять.
- **Градиентов нет.** Заливка только плоская. Единственное исключение —
  разделительные волосяные линии во втором варианте (`/v2`): по просьбе
  заказчика они гаснут к краям (`from-transparent via-hair-strong
  to-transparent`). Заливки плоскостей это не касается.
- Карточка = `border border-hair bg-white` + четыре уголка-засечки `Corner`
  (`h-3 w-3 border-t border-l border-ink`). Это фирменный приём, отсылка
  к чертёжной подаче — сохранять при появлении новых карточек.
- Поля ввода — подчёркивание `border-b`, не рамка. Фокус: `border-ink`.
- Сетка hero: 12 колонок, контент `lg:col-span-7 xl:col-span-8`,
  форма `lg:col-span-5 xl:col-span-4` со `sticky top-24`.

## Движение

```yaml
easing:
  primary: cubic-bezier(0.16, 1, 0.3, 1)   # --ease-out-expo
durations:
  micro:   200–350ms    # чекбокс, смена состояния
  ui:      500–900ms    # появление блоков
  image:   1200ms       # выход главного кадра
stagger: 60ms
```

Библиотека — `motion/react` (не GSAP, не Framer Motion старого API).

**Правила движения**

- Базовый вход: `opacity 0 → 1`, `y 26 → 0`, 0.9s, задержка `0.06 * i`.
- Главный кадр: `scale 0.985 → 1`, 1.2s, задержка 0.25s.
- Живут только `transform` и `opacity`. Анимировать `width`, `height`, `top`
  нельзя — кроме `height: auto` на схлопывании текста ошибки.
- Постоянные циклы допустимы, если почти незаметны: «дыхание» кадра
  `y: [0, -9, 0]` за 9s. Ничего быстрого и мигающего.
- Стрелка на кнопке уезжает по `gap` при hover — жест «вперёд», не вращение.
- `prefers-reduced-motion` обрабатывается глобально в `globals.css` — не
  дублировать в компонентах.

## Чего в этом проекте не делать

Список из прямых слов заказчика и из логики системы.

1. **Никакого фонового декора.** Блобы, размытые пятна, кольца, сетки, «шум»,
   декоративные градиентные ореолы — заказчик их не любит, сказано явно.
   Фон ровный белый, всегда.
2. Не скруглять. Не добавлять тени. Не добавлять стекло/blur.
3. Не вводить второй акцентный цвет. Охра `oak` — единственный.
4. Не менять `Inter Tight` на «премиальные» гарнитуры вроде Clash Display:
   у них нет кириллицы, а весь текст русский.
5. Не заполнять низ страницы по своей инициативе — заказчик сказал
   «пока ничего не делаем» про блоки ниже второго.
6. Не трогать точки привязки выносок `callouts` в `construction.tsx` на глаз:
   они вычислены сканированием пикселей рендера (см. `CLAUDE.md`).
7. Не добавлять эмодзи в интерфейс.

## Референсы других брендов

В `design-refs/` лежат разборы дизайн-систем Airbnb и Starbucks
(из [awesome-design-md](https://github.com/VoltAgent/awesome-design-md)).

Это **справочный материал, а не образец для копирования.** Обе системы
скруглённые и цветные, то есть противоположны нашей. Брать оттуда стоит
только приёмы подачи, а не токены:

- **Airbnb** — щедрость воздуха, фотография как главный носитель эмоции,
  сдержанный вес заголовков там, где работает картинка.
- **Starbucks** — тёплая нейтральная база и крафтовая интонация текста.

Чего оттуда **не** брать: палитры (`#ff385c`, зелёный Starbucks), гарнитуры,
радиусы, капсульные кнопки.
