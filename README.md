# Reuve Craft — лендинг журнального столика

Минималистичный одностраничник для дизайнерского журнального столика
(массив дуба + закалённое стекло). Белый фон, плотный гротеск, выноски-линии
от изделия — по референсам TAKT / ASTER.

## Стек

- **Next.js 16** (App Router, Turbopack) + **TypeScript**, статический экспорт
- **Tailwind CSS 4** — токены темы в `src/app/globals.css`
- **Motion** (`motion/react`) — появления, параллакс, отрисовка линий-выносок
- **Supabase** — таблица заявок, браузер пишет в неё напрямую

## Запуск

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # прод-сборка
npm start
```

## Заявки

Сайт статический, серверного маршрута нет: `sendLead` из `src/lib/leads.ts`
пишет строку прямо в таблицу `reuve_leads` в Supabase. Anon-ключ лежит в коде
открыто — это нормально, доступ ограничен политикой RLS «только INSERT»,
читать заявки через него нельзя. Бот-заполнители отсекаются honeypot-полем,
UTM-метки из адреса попадают в колонку `source`.

Уведомление в Telegram шлёт триггер на стороне базы, поэтому токен бота
в браузер не попадает. Разворачивается это так:

1. Supabase → SQL Editor → выполнить `supabase/schema.sql`
2. затем `supabase/telegram-notify.sql`, подставив свои `BOT_TOKEN` и `CHAT_ID`
   прямо в редакторе (в файл их не сохранять — репозиторий публичный)

Заявки смотреть в дашборде Supabase, таблица `public.reuve_leads`.

## Деплой

Пуш в `master` запускает `.github/workflows/deploy.yml`: `npm run build`
кладёт статику в `out/`, дальше её забирает GitHub Pages. В настройках
репозитория Pages должен быть переключён на источник **GitHub Actions**.

Две переменные репозитория (Settings → Secrets and variables → Actions → Variables):

| Переменная | Значение |
| --- | --- |
| `BASE_PATH` | `/reuve-craft`, пока сайт в подпапке `reuvenation.github.io`; на своём домене — пустая |
| `SITE_URL` | канонический адрес сайта, попадает в метатеги, sitemap и robots |

При переезде на свой домен: положить домен в `public/CNAME`, очистить
`BASE_PATH`, поменять `SITE_URL` — и перезапустить workflow.

## Выноски на изображении

Координаты точек привязки заданы в долях кадра 3/4 (`callouts` в
`construction.tsx`) и пересчитываются в систему `viewBox 1100 × 460`.
Кадры светлого дуба и тёмного ореха сняты в одной раскадровке, поэтому
выноски совпадают при смене отделки. Если менять картинку — пересчитать
`anchor` (доли ширины/высоты изображения).

## SEO

- `<h1>` с ключевым запросом, микроразметка Product (JSON-LD) на главной
